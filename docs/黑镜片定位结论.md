# 光影下镜片黑屏：最终结论与修复记录（2026-10-10 实机验证通过）

> 本文件取代早期版本里「未修复 / 建议光影下禁用画中画」的结论。
> 黑镜片问题已在实机上修复并验证：Fabric 26.3 + Iris 1.11.7 + Complementary，
> 25 倍镜，光影开/关均正常。相关代码均已提交推送。

---

## 一、最终根因（三个，缺一不可）

1. **抓帧早于 Iris 最终合成。**
   `GlCommandEncoder#copyTextureToTexture` 是**立即执行**的 `glBlitFramebuffer`（字节码实读），
   读的是源纹理【此刻】的内容；而 Iris 的最终合成（`FinalPassRenderer#renderFinalPass`）
   是用 `createRenderPass` **记录**进命令流、稍后才执行的。于是拷贝永远抢跑——
   拿到的是上一帧的旧画面（开镜瞬间"有内容"=旧帧、开满后"格纹"=旧帧中心被放大 25 倍、
   二次渲染纯黑=旧画面都还没写入）。

2. **镜内那一遍把枪身也画了进去。**
   Iris 把手部渲染搬进了 `LevelRenderer#render` 内部，镜内那一遍（自己调一次 render）
   于是包含枪身——镜内画面正中央是一块黑。无光影路径没有这个问题
   （手部在 render 之后才画）。

3. **准星与目镜框被合成盖住。**
   合成排在手持渲染之后，把先画好的准星/目镜框整片覆盖。

早期版本记录的「拷错纹理」假设**不准确**——后来的字节码实读证明问题不是"拷了哪张纹理"，
而是"拷得太早"。见下文"过程记录"。

## 二、修复方式（对应上面三点）

| 根因 | 修复 | 落点 |
|---|---|---|
| 抓帧太早 | 把拷贝从立即执行的 `copyTextureToTexture` 改成**记录进同一命令流的 blit 通道**（`deferredBlitCopy`，用 vanilla 公开的 `ENTITY_OUTLINE_BLIT` 管线），排在 Iris 最终合成之后执行；并挂在镜内那一遍的 finalize TAIL（`IrisLevelFinalScopePipMixin`） | `ScopePipRenderer.deferredBlitCopy()` / `IrisLevelFinalScopePipMixin` |
| 镜内有枪身 | 镜内那一遍取消 Iris 的手部渲染（`IrisHandScopePassMixin` 取消 `HandRenderer.renderSolid/renderTranslucent`） | `IrisHandScopePassMixin` |
| 准星被盖 | 把准星与目镜框冻结快照，在 PIP 合成之后重画：手持矩阵在**提交时**抓取（与 `ScopeMaskGeometry` 同款做法），重画点放在 `renderItemInHand` RETURN | `ScopeFinalOverlayState` / `ScopeBodyRenderTypes` / 两个 `IReticleRenderer` 实现 |

同批修复的相邻问题：

- 旗标时序：`scopePassReadyToCapture` 必须在 `levelRenderer.render()` **之前**置位
  （finalize 在 render 内部触发），否则拷贝永远静默跳过。
- `sceneCaptured` 分模式处理：光影路径由成功拷贝置位；无光影路径在镜内那一遍直接置位
  （曾误删，导致无光影变倍镜镜片不更新——回归，已修）。
- Distant Horizons 远景 LOD 不随倍率缩放：DH 每帧只接受一次投影写入，
  镜内那一遍的窄投影写入被它的 `getNewMvmMatrix` 旗标挡掉。新增
  `DistantHorizonsCompat`，在窄投影写入前重新立起旗标、镜内结束后用主投影重写并复位。
- 开镜/收镜瞬间视野抽动（高倍镜）：FOV 抑制依赖"上一帧掩码"，开镜第一帧与收镜最后一帧
  会让整屏 FOV 按 `1+(Z-1)·progress` 跳一下（25 倍镜下 progress=0.05 就是 2.2 倍）。
  改为粘性判据：progress 从 0 转正即抑制，直到本次开镜过程结束（`ScopePipRenderer.suppressesWorldFovZoom`）。

## 三、给接手者的复现与验证方法

1. 实例装 Iris + 光影包（Complementary 已验证）。
2. `tacz-client.toml`：`ScopeMaskEnable=true`、`ScopePipEnable=true`、
   `ScopePipAllowShaderPacks=true`、`ScopePipRerender=true`。
3. 进世界、开光影、拿 4 倍以上的枪、开镜。
4. 预期：镜片显示放大后的世界；准星与目镜框正常；转动视角准星跟随；收镜后主画面无异常。
5. 日志关键行：`grep "TACZ Scope" logs/latest.log`，正常时应看到
   `Scope PIP second-render pass captured after Iris' final composite` 与
   `Redrew scope reticle after shader-pack PIP composite`。

# 过程记录（历史档案）

> 以下内容保留自早期诊断，作为"如何一路排错"的过程记录。
> 其中「拷错纹理」的猜测已被上面的最终结论修正；第六节的"方案 A：光影下禁用画中画"
> 也已不再是推荐方案——问题已直接修复。

## 早期结论（已被修正）

**光影下，画中画的"场景拷贝"抓到的是空的（黑）。** 合成路径本身跑得通
（品红色能铺满镜片、有随开镜进度生长的动画），它只是把一张空图放大后画进了镜片。
（修正：不是"拷错纹理"，是"拷得太早"——Iris 的最终合成那时还没执行。）

## 证据链（日志原文，2026-10-10 早期测试）

```
[TACZ Scope] Scope PIP gate -> ACTIVE                                             ← 开镜：闸门全过
[TACZ Scope] Ocular mask drawn: 288 indices from 7 batches                        ← 遮罩正常
[TACZ Scope] Scope PIP target allocated at 3440x1440 (RGBA8_UNORM, depth=false)  ← 离屏目标建好
[TACZ Scope] Scope PIP active: reprojecting a 3440x1440 scene copy at 25.0x magnification
[TACZ Scope] Iris scope-mask bridge active (mode=2, textureUnit=31, textureId=1510)
```

品红标记测试（`ScopePipDebugPaintLens=true`）：镜片品红铺满且随开镜进度生长——
证明合成在跑、素材是空的。这条测试至今仍是排查"合成 vs 素材"问题的首选工具。

## 关键转折：角落探针

把离屏纹理原样画到屏幕左上角（绕过遮罩/倍率/剪裁）后，实机看到：
**镜内画面有内容（随倍率缩放），但中央有一块黑（枪身）**。
这一条同时证明了两件事：拷贝链路已经修通（画面随倍率走），
黑屏是枪身被画进了镜内那一遍。

## 为什么此前一直查不出来

- 默认配置下两个开关（`ScopePipEnable`、`ScopePipAllowShaderPacks`）都关着，
  画中画根本不运行、日志全无——测试者容易误判"与画中画无关"。
- 上游作者在 `RenderConfig` 里的注释说过："这个症状靠静态分析已经连错四次。"
  本次最终定位靠的是**实机观察 + 字节码实读**两件事合起来，缺一不可。
