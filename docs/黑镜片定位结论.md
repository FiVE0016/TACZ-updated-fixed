# 黑镜片 / 品红镜片：实测结论（2026-10-10）

> 这份文件记录一次**真实的实机诊断**，取代 README 里原先"尚未定位到根因"的说法。
> 操作：仓库主人在自己的实例（Fabric 26.3 + Iris 1.11.7 + Complementary）里开镜观察。
> 分析者（AI）读取 `latest.log` 与源码。

---

## 一、结论一句话

**光影下，画中画的"场景拷贝"抓到的是空的（黑）——它拷错了纹理。**
合成路径本身跑得通（品红色能铺满镜片、有随开镜进度生长的动画），
它只是把一张空图放大后画进了镜片。

## 二、证据链（日志原文）

测试条件：`ScopeMaskEnable=true`、`ScopePipEnable=true`、
`ScopePipAllowShaderPacks=true`、`ScopePipDebugPaintLens=true`（镜片涂品红）、
`ScopePipRerender=false`（重投影模式）。

```
[TACZ Scope] Scope PIP gate -> held gun has no scope attachment with zoom > 1   ← 还没举枪
[TACZ Scope] Scope PIP gate -> no ocular mask produced                            ← 举枪但未开镜
[TACZ Scope] Scope PIP gate -> ACTIVE                                             ← 开镜：七道闸门全过
[TACZ Scope] Ocular mask drawn: 288 indices from 7 batches                        ← 遮罩正常
[TACZ Scope] Scope PIP target allocated at 3440x1440 (RGBA8_UNORM, depth=false)  ← 离屏目标建好
[TACZ Scope] Scope PIP active: reprojecting a 3440x1440 scene copy at 25.0x magnification
[TACZ Scope] Iris scope-mask bridge active (mode=2, textureUnit=31, textureId=1510)
```

**仓库主人的目视所见**（这是最关键的一条）：

- 开镜后镜片是**品红色** → 合成那一遍**确实在跑**，画的是"涂色"而不是"看不见的世界"
- 从腰射到开镜，镜片内有**品红色铺满的动画** → 倍率随开镜进度增长、采样范围从中心扩张，符合代码设计
- **不瞄准时高倍镜仍是黑色** → 那是目镜遮罩的实心深色板，属正常（未开镜时不该透视）

## 三、代码层面的定位

`ScopePipRenderer.captureScene()`（约 913-960 行）执行：

```java
RenderTarget main = mc.gameRenderer.mainRenderTarget();
GpuTexture source = main.getColorTexture();          // ← 问题在这里
...
encoder.copyTextureToTexture(source, copy.getColorTexture(), 0,0,0,0,0, w, h);
```

代码注释写的预期是：

> Iris 把手部渲染搬进了 `LevelRenderer#render` 内部，于是「`LevelRenderer#render` 之后」
> 意味着整条 Iris 管线（延迟光照、composite、色调映射、手部）**全部跑完** ——
> 抓到的正是最终画面。

**实测结果与这个预期不符**：抓到的画面是空的。

最可能的解释（**尚未最终证实**）：**光影开启时，最终画面并不存在于 `mainRenderTarget()` 的颜色纹理里。**
Iris 用自己的渲染目标链，最终结果经它的 `final` 程序写屏；
主 render target 的颜色纹理在这个时刻可能仍是空的/中间态。

## 四、为什么"重投影模式"必然受此影响

`ScopePipRerender=false`（默认）时，镜内画面 **100% 依赖那张拷贝** —— 拷贝空 = 镜内空。

而 `ScopePipRerender=true`（二次渲染模式）是**用窄 FOV 把世界真画一遍**，不依赖拷贝。
**所以二次渲染模式在光影下理论上应该能出图** —— 这一条**尚未测试**，是下一步最值得做的实验：

```
tacz-client.toml:
  ScopePipRerender = true
```
（代价：每帧多跑一整遍世界渲染，帧率大约腰斩。）

## 五、为什么此前一直查不出来

- README 原先写"触发条件之一是 `ScopePipEnable = true`"，**这是对的**，
  但漏了第二个必需开关 `ScopePipAllowShaderPacks`（默认 false）。
  只开第一个时，光影下画中画**根本不会运行**，所以：
  - 在默认配置下测试 → 什么日志都没有（`reportGate()` 第一行就 `return`）
  - 让人误以为"黑镜片与画中画无关"
- 上游作者在 `RenderConfig` 里的注释也说过："这个症状靠静态分析已经连错四次"。
  本次能定位，靠的是**实机 + 品红标记**，不是读代码。

## 六、处理选项（给接手的人）

| 方案 | 代价 | 建议 |
|---|---|---|
| **A. 光影下禁用画中画，退回整屏变焦** | 0（整屏变焦本来就工作正常） | ✅ **推荐**。改 `subsystems` 的开关判定：光影开着时让 `allowShaderPacks()` 返回 false，或在 `inactiveReason()` 里加一条。也可以在 `ScopePipAllowShaderPacks` 的默认值与文档上收口 |
| **B. 给二次渲染模式补上光影下出图的实测** | 一次实机测试 | 先测 `ScopePipRerender=true`。若真能出图，可把光影下的默认改成它，代价是帧率 |
| **C. 找到 Iris 那条"最终画面"纹理并改拷它** | 高（要摸 Iris 内部约定，上游已试过三种反射全死） | ❌ 不建议，除非有人愿意长期啃 |
| **D. 什么都不做** | 0 | ❌ 不可接受：用户会看到"镜片全黑/全品红" |

**A 的成本几乎为零，且不需要任何新的渲染知识** —— 这是当前最合理的收口方式。
把"光影下镜内不放大"从一个**看不懂的 bug**，变成一条**写得明明白白的行为**。
